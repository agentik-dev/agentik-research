## What it says
- Method (Sections 3 and 4.1): AGENTbench (new; 138 Python tasks from 12 repositories that each have a developer-written context file) and SWE-bench Lite (300 tasks, no context files). Agents: Claude Code with Sonnet 4.5, Codex with GPT-5.2 and GPT-5.1 mini, and Qwen Code with Qwen3-30b-coder; one run per task. Three settings: no context file, a file generated by the agent's own init command, and a developer-written file.
- Result (Section 4.2, Table 2): generated files lowered the resolution rate by 0.5 percent on SWE-bench Lite and 2 percent on AGENTbench and raised cost by about 20 and 23 percent. Developer-written files gave small gains for all agents except Claude Code, at up to 19 percent more cost.
- Why (Section 4.3): agents followed the files and did more testing, searching and reading; the authors read this as extra requirements making tasks harder, not as agents ignoring the file. Context files did not cut the steps needed to reach the files the fix touched.
- Section 4.2 also reports that when existing documentation was removed, generated files helped (about 2.7 percent).
- Advice the authors draw: keep human-written context files to minimal requirements.

## Limits
- Python only; task success only (no code quality or security); one run per task. The paper's introduction (3 percent drop, 4 percent gain) and Section 4.2 (0.5 and 2 percent) give different figures for the same comparison.
- It tests file content, not file length, so it does not show that a longer file is worse than a shorter one; it shows that adding instructions can cost steps and money without raising success.
- Claude Code was left out of one experiment for cost.

## Also (question 3)
- The page I opened on 2026-10-14 lists three versions: v1 on 12 February 2026, v2 on 23 June 2026 and v3 on 29 September 2026. The full text I read (the arXiv HTML page, labelled v3) names the new benchmark CTXbench: 138 instances from 12 repositories that have developer-committed context files; SWE-bench Lite has 300 tasks from 11 repositories. The note above says AGENTbench, which may be the name in an earlier version; I did not check v1.
- Numbers in the v3 text: generated files changed success by -0.5 points on SWE-bench Lite and -2 points on CTXbench, not significant (p = 0.87 and 0.37). Developer-written files versus none: +2.4 points on average, not significant (p = 0.21). Developer versus generated files: about 7 points, significant (p = 0.038). Generated files raised cost by about 20 percent and 23 percent; developer files raised cost by up to 19 percent.
- Of 12 developer files, 8 contain a repository overview; overviews did not reduce the steps needed to reach the files the fix changed. Instruction following was close: a tool named in the file was used about 1.6 times per instance, against under 0.01 times when not named. The abstract advises writing context files only for non-standard practices, and evaluating before adoption.
