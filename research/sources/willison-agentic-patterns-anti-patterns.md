## What it says
- A good pull request made with an agent: the author is confident the code works, the change is small enough to review efficiently, and it explains the higher-level goal, ideally with links to the relevant issues or specifications.
- The author should show the work was done: notes on manual testing, comments on implementation choices, or screenshots or video of the feature working.
- Agents write convincing-looking pull request descriptions, so the author must review and validate them before submitting. The page calls it rude to expect others to read text the author has not checked.
- Unreviewed agent output shifts the first review pass onto collaborators: "The initial review pass is your responsibility, not something you should farm out to others."

## Limits
- One practitioner's rules for open-source pull requests. No data, and the page shows no date or byline beyond the site's ownership.
