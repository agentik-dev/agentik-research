## What it says
- "Available modes": six modes, `default` (shown as Manual), `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`. The page's best-for column gives `bypassPermissions` as isolated containers and VMs only and `dontAsk` as locked-down CI and scripts. From Claude Code v2.1.283 auto mode is the built-in starting mode for interactive terminal and VS Code sessions; before that only on Pro, Max and Team plans.
- Auto mode needs, on the Anthropic API, Opus 4.6 or later, Sonnet 4.6 or later, Haiku 5.5 or a Fable model; on Bedrock, Google Cloud's Agent Platform and Foundry only Sonnet 5 or later, Opus 4.7 or later, Haiku 5.5 and Fable models. Older models (Sonnet 4.5, Opus 4.5, Haiku 4.5, claude-3) are not supported on any provider.
- "How the classifier evaluates actions": a fixed order, first match wins. (1) allow, ask and deny rules resolve at once, with exceptions (protected-path writes still go to the classifier; no allow rule approves `rm` or `rmdir` on a critical path). (2) Read-only actions and edits in the working directory are auto-approved. (3) Everything else goes to the classifier. (4) On a block, Claude receives the reason, usually the name of the matched rule such as `[Data Exfiltration]`. On entering auto mode, broad allow rules are dropped: `Bash(*)`, wildcard interpreters such as `Bash(python*)`, package-manager run commands, `Agent` rules and `Monitor` rules; narrow rules such as `Bash(npm test)` stay.
- What the classifier sees in Claude Code's own requests: user messages, tool calls other than read-only lookups, and CLAUDE.md content. Tool results are stripped, so hostile text in a file or web page cannot reach the classifier directly. A separate server-side probe scans incoming tool results. Claude Code also runs `git status` itself before a command that would discard uncommitted work and shows the classifier what is unsaved.
- "Cost and latency": the classifier runs on Claude Sonnet 5 by default, not on the session model. On Enterprise plans and API or cloud-provider accounts the classifier calls count toward token usage. Each check sends part of the transcript plus the pending action, adding a round trip, mostly for shell commands and network operations.
- "What the classifier blocks by default": downloading and executing code (`curl | bash`), sending sensitive data to external endpoints, production deploys and migrations, mass cloud-storage deletion, force push, `git reset --hard`, `git checkout -- .`, `git restore .`, `git clean -fd`, `git stash drop` and `git stash clear`, `terraform destroy` and its peers, disabling CI checks, and a flag that disarms a safety guard such as `--insecure`. From v2.1.205 it also blocks a recursive forced delete whose target is a shell variable not assigned anywhere in the visible conversation. From v2.1.203 it blocks content from a sensitive local store entering a commit, push, PR text or paste. It also blocks "Writes to a shared compute cluster that reach beyond the resource you named" (for example a label selector or `--all`). The page lists no rule for killing local processes.
- Allowed by default: local file operations in the working directory, installing dependencies declared in lock files or manifests, reading `.env` and sending credentials to their matching API, read-only HTTP, and pushing to any branch of the working repository (non-default deploy-named branches such as `production` or `gh-pages` are judged on their own terms). `claude auto-mode defaults` prints the full rule lists.
- Boundaries stated in conversation count as a block signal, but are not stored as rules: the classifier re-reads them from the transcript, so compaction can drop one. For a hard guarantee the page says to add a deny rule.
- "When auto mode falls back": 3 blocks in a row or 20 in total pause auto mode and resume prompting; the thresholds are not configurable. A non-interactive `-p` run without `--permission-prompt-tool` has no prompt to fall back to: at a threshold the action does not run and Claude keeps working; Claude Code does not stop the run. If the classifier gives no verdict because a separate safety check refused its request, or its response does not parse, the action is denied without a notification. Under server-side review the turn stops after ten responses in a row with no verdict. Auto mode can be turned off per organization with `permissions.disableAutoMode`.
- Subagents: the classifier checks the task description before a subagent starts, each action while it runs (a `permissionMode` in the subagent's frontmatter is ignored), and its work and final report when it finishes.
- "Protected paths": writes are never auto-approved except in bypass mode. Protected directories include `.git`, `.vscode`, `.idea`, `.husky`, `.devcontainer` and `.claude` (with exceptions, including Claude's own git worktrees under `.claude/worktrees/`); protected files include `.gitconfig`, shell profiles, `.npmrc`, `.mcp.json` and `.claude.json`. In `dontAsk` mode they are denied; in `auto` they go to the classifier. An allow rule in a settings file does not pre-approve them.
- "Critical paths": Claude Code never lets an allow rule, or a PreToolUse hook returning allow, approve an `rm` or `rmdir` aimed at the filesystem root, a top-level directory, the home directory, or the working directory and its parents; a deny rule still blocks. It also treats `rm -rf "$DIR"/*` as critical because the command becomes a removal from root when the variable is empty (the page suggests `"${DIR:?}"` or a literal path). It looks inside subshells, command substitutions and `bash -c` scripts. In `auto` and `bypassPermissions` the terminal prompt shows a two-minute countdown and denies on expiry; after three unanswered prompts in a session it denies at once. In `auto` with no terminal, such as `-p`, it denies immediately. Needs v2.1.281 or later for the countdown.
- "Skip all checks with bypassPermissions mode": disables prompts and safety checks. Claude Code refuses to start in it as root or under `sudo` (the check is skipped inside a recognized sandbox). Cloud sessions ignore `defaultMode: "bypassPermissions"` and `"dontAsk"` from settings files. The warning reads that the mode "offers no protection against prompt injection or unintended actions".
