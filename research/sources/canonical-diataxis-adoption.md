## What it says
- The post is the first of four "pillars" in Canonical's documentation transformation project and covers direction: what makes documentation good. Its guiding principle is that "good documentation serves the needs of its users", and it picks Diátaxis as the lightweight framework to apply it.
- The four types are tutorials, how-to guides, reference and explanation. Each document should fit exactly one type, and content of another type should move elsewhere.
- Applied so far to Anbox Cloud, Charmed Kubeflow, the Juju Operator Lifecycle Manager, the OpenStack Charms guide and the Ubuntu Core docs.
- Caveat in the author's words: "As a lens, Diátaxis is unforgiving." It tends to make existing documentation look worse at first because it exposes gaps and misplaced content. The project is ongoing and the post says it will take time.

## Limits
- A practitioner's account from the framework's own community. It reports no measured outcome, no reader numbers and no before-and-after comparison.
- The post does not say who created Diátaxis. A web search result named the same author as its creator; I did not confirm that on diataxis.fr.
