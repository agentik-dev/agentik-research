## What it says
- Purpose: delegated and headless Claude Code runs billed to an Anthropic API key (a Console project) instead of the interactive Team Premium subscription seat. Interactive `claude` is untouched. Three lanes: API-billed (headless `claude --bare` through the API wrapper), subscription (the seat, plain `claude`), local model (a loopback router plus a launcher).
- The wrapper runs `claude --bare`, whose auth the README says (citing `claude --help`) is strictly an API key or an `apiKeyHelper`, never OAuth or the keychain. It also unsets the OAuth and auth-token variables in its own process only. `--bare` skips hooks, LSP, plugin sync, auto-memory and CLAUDE.md discovery.
- Profiles `review` (Sonnet 5, medium effort, JSON schema output), `explore` (Sonnet 5, low) and `analyze` (Opus 5, high) are read-only. A correction is recorded: the first design used `--allowedTools` plus `dontAsk`, the README claimed a probe had confirmed Bash and Edit were refused, and that was wrong, because `--allowedTools` pre-approves rather than restricts. A red team reproduced Bash running inside a profile run; the fix is `--tools "Read Grep Glob"`.
- `Read` is not confined to `--add-dir`: a probe read the age private key from a delegate whose `--add-dir` pointed at a scratch folder. The threat named is prompt injection through content the delegate reads. Mitigations in order: never delegate over untrusted content; a credential-path deny list (defence in depth, not a boundary); Claude Code's OS sandbox with `failIfUnavailable`. Deny-rule path syntax is `~/...` or `//...`; a single leading slash matches nothing, silently. Deny-rule blocks do not appear in `permission_denials`.
- Containment is an allow-list: under `--profile` the wrapper builds the child's argv itself and accepts five caller flags (`--model`, `--fallback-model`, `--effort`, `--max-budget-usd`, `--add-dir`). An earlier deny-list design was defeated four ways (a misordered `--profile`, a flag-shaped prompt, capability flags passing through, an unlisted value-taking flag shifting scan parity and dropping the spend ceiling). The prompt goes on stdin, never argv.
- Spend ceiling measured with a $0.01 cap on a six-file task: `error_max_budget_usd`, 1 of about 6 turns done, actual spend $0.0117 (1.2 times the cap), empty result, wrapper exit 1. The cap is checked between model requests. The README concludes "A tight cap is the expensive choice, not the safe one", so profiles default to a $10 ceiling meant to catch runaways.
- Usage log: one metadata line per run (profile, models, cost, turns, duration, cache tokens, names of denied tools); no prompt, result or tool input. It is unbounded with no rotation. Run dirs hold `run.json` and `progress.json` per API child, pruned after 7 days, read by the status tool (lane `api`).
- Fan-out: `--max-budget-usd` is per process, so N shards at the default $10 expose $N0. The fan-out tool holds one pool; each shard reserves before launch and settles at its real cost, so settled plus in-flight reserves never exceed the budget. Per-shard ceilings are deflated by 1.35. Statuses: ok, degenerate, error, budget_exhausted, skipped_budget, timeout, interrupted, unparseable. Ctrl-C kills the delegates.
- Cost lanes, never summed: API (real dollars from the usage log); subscription (equivalent dollars at list rates from the per-model usage Claude Code records in its config file; no cash left the account); local (zero dollars, tokens and wall time from the router's ledger, with a Sonnet-list figure that sizes what it spared). Stated measurement: $3.13 of API spend beside $155.78 of seat-absorbed work, about $50 per $1 of cash. No date is given for these two figures.
- Prompt-cache saving on the API lane, measured on the fan-out: $4.49 uncached against $3.12 actual, a 30% saving.
- The price table self-checks against billing (cache figure withheld if prediction and bill differ by more than 2%). It caught a promotional-rate error: the pricing page listed $2/$10 for Sonnet 5 through 2026-08-31, but solving for the rate actually billed showed the standard $3/$15 predicting within 0.00% and the promotional rate missing by 33%.
- Efficiency measured on the eight-shard fan-out: 33% of spend bought nothing; cache hit rate 70%; output 46% of cost; $0.52 per usable run; $0.21 per finding; cost dispersion 1.7 times (median $0.41, max $0.71 for identical prompts).
- Fan-out cost notes (8-shard `review` fan-out over an 849-line file): 4 to 10 turns, $0.20 to $0.71 per shard, $3.12 for eight; identical prompts varied up to 1.75 times; two of eight shards ran 8 to 10 turns, cost $1.02 combined and returned a schema-valid placeholder while the envelope read success; staggered versus simultaneous launch was inconclusive; no wall-clock bound exists (shards 88 to 345 s, four simultaneous finished in 4 min 14 s, an Opus high-effort review took about 6 min); four simultaneous runs wrote 8 clean log lines on a local filesystem.
- Prompt cache economics: two identical trivial `review` runs cost $0.0133 then $0.0055 (cache creation 0, cache read 4,475 tokens); reads bill at about 0.1 times input and writes at about 1.25 times; the shared prefix is only about 4.5k tokens, so the figures do not extrapolate. Every profile sets `--exclude-dynamic-system-prompt-sections` to keep cwd, env and git status out of the cached prefix.
- Session-window (5-hour, weekly) utilisation is not written to any local file; the config file records only the rate-limit tier; the README points to `/usage` inside an interactive session.
- Lane 3: the router listens on loopback and routes by the request body's model name; `claude-*` models go upstream with headers byte for byte (seat kept), `local/*` or a name with a colon tag goes to an Anthropic-format local backend. On local routes it drops the `<total_tokens>` reminder (turn two prefill 35.6 s with it, 0.38 s without), injects and clamps effort (4,299 thinking tokens and 4 min 56 s for a three-line file when unpinned; 45 s at low), clamps `max_tokens` to 8192 (Claude Code asks for 32000; about 35 minutes at roughly 15 tok/s), serialises requests (single-slot runner), emits SSE pings during silent prefill (300-second watchdog), and answers `count_tokens` with a chars/4 estimate.
- Local model sizing (Qwen 3.8 27B q8_0, Ollama 0.33.2, an Apple Silicon laptop with 128 GB): prefill about 87 to 230 tok/s; generation 11 tok/s prose and about 25 tok/s for JSON and tool calls. Tool schemas are the prompt: a 3-tool agent turn is about 5.4k tokens, a 50-tool one about 26k (146 s), a 54-tool one about 31k (172 s; its turn two repeated the full prefill, cause not isolated, n=1). Guidance: under about 8 tools and 15k tokens per local turn.
- Unnamed subagents default to `sonnet`, not local, for that reason. Model names decide the route; nothing else does; forks stay on the main model. While the base URL is non-Anthropic, Claude Code disables Remote Control and voice dictation.
- Credentials: loopback keys stored with sops and age outside the repo; a suffix-based `encrypted_regex` replaced a name list after a cleartext leak was reproduced on 2026-09-05 with an `openrouter_key`; an API key once committed (encrypted to two identities that could no longer decrypt it) was removed and revoked on 2026-09-05, and the README says the API lane had never been run on that machine.
- Tests: eight stub-driven suites plus a hygiene suite; only the flag-pinning suite touches the real `claude` binary (it parses `--help` and skips when absent). The router suite is stated at 87 checks.
- The interim orchestrator demo (`queue-mvp`) walks mock jobs up a model ladder (sonnet junior, opus senior, fable tech lead) with an objective acceptance bar and escalation; it targets a private job-queue service, and `--dry-run` uses canned responses at zero spend.
- Feedback log (2026-08-13 and 2026-08-14): a help text executed backticked words as command substitutions; profile runs refused a prompt file when stdin was /dev/null; an `implement` run on Opus spent 53 turns and $6.44 and emitted only its test file, and a continuation with an output-discipline header finished in 17 turns and $1.93; an implement run spread files over 8 turns, the envelope kept only the final message, and about $2.70 was wasted.

## Limits
- One owner, one machine, one model family; the measurements are single runs or an eight-shard fan-out. Several cost figures carry no date.
- The README is partly stale against later notes: NICE_TO_HAVE.md says its claim that the Explore override is an inlined copy is out of date (the override is built at launch). Its opening says profile delegates have Read, Grep and Glob, while the wrapper's own comments say Grep and Glob do not exist under `--bare`, so a delegate has Read alone.
- The subscription-lane figure is read from a per-project "last model usage" field in Claude Code's config file; the README does not say whether that field is cumulative, so the $155.78 may undercount (a reading of the code, not a claim in the README).
