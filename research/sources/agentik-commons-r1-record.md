## What it says
- Record r1 is dated 2026-10-13 and was folded in after a refuter (adversarial review) round, and the line adds that for an architecture change the round comes before any code (line 3). The owner's instruction is timed 2026-10-13, 14:15 (line 5): one git-style `agentik` front door that runs `agentik-<tool>` from PATH, each plugin installable alone, old names kept as aliases for a while, and a public commons repo holding the guide, the canonical hygiene scan, shared code and one marketplace.
- The problem (§1, lines 9-11): "Five tools, five naming schemes, three marketplace rules. One tool takes verbs as flags." One name (the session tool's) was at once a marketplace, a state folder and a config folder.
- The survey (§2.1, lines 15-25) lists each tool's executable and verbs on 2026-10-13. Relay is a Go binary with 12 public verbs and one internal `hook`. Session is a shell launcher with 12 public verbs, 4 internal ones, and frozen code trees in a state folder. Decisions is a uv tool with 8 verbs. Respeak has no executable. Agents is 8 separate scripts linked into one bin folder, one of which takes its verbs as flags. The `bounded` and `hygiene` scripts match across all five repos (the record gives the identifier acc3498d); `doclint` matches across three.
- Plugins (§2.2, lines 27-37): five plugins, each with its own marketplace; the agents plugin was disabled at survey time; each plugin's `allowed-tools` names its CLI; plugin data folders were empty.
- Callers outside the five repos (§2.3, lines 39-53): 27 session briefs in consumer repos (3 read by running launchers), pasted start lines, subagent types, repo config, generated CLAUDE.md lines, a repo template, and the owner's machine settings. Files with hits: 50 for the old session CLI name, 443 for the old bare relay verb form (mostly prose), 140 for the old bare decisions verb form, 26 for the agents tool names, 29 for the old relay subagent prefix. The files and lines sit in private rollout notes the record does not publish.
- Facts that bind the design (§2.4, lines 55-63): plugin names have no aliases, so a plugin rename renames every slash command and agent; cross-repo `git-subdir` entries validate (including `ref`, `sha` and `file://` urls); decisions writes its own command name into every generated block, so new wording makes each `render --check` stale; relay's guards match by command name, so a new spelling gets past both; session's README test requires the old CLI; a running launcher keeps its interpreter and code tree until the owner restarts it (a RESPAWN restarts only `claude`), and three launchers were running during the survey; the hygiene scan's exit codes were the reverse of the convention (2 on a hit, 1 on usage).
- Front door (§3, lines 65-73): POSIX `sh` under 100 lines; name checked against a lowercase-hyphen pattern; `exec` of `agentik-<tool>` with arguments unchanged; reads and writes nothing; no old-name resolution; list, help and version exit 0 even when nothing is found; exit 2 for usage; exit 3 when the tool is not on PATH, naming its repo (the record says relay's commands already used 3 this way); each tool repo vendors a hash-pinned copy and its `make install` copies it to the bin folder (D3).
- Names (§4.1, lines 77-87): `agentik-<tool>` for each tool; old names stay as aliases until 2026-12-31. Aliases (§4.3, lines 101-107) are symlinks with no shim, so the hook path is unchanged; under the old name, on a terminal, for a non-hook verb, one stderr line says the name was renamed; hooks, pipes and gates see nothing. The end date can only move later, and r2 ends the aliases once the `renamed` scan finds no live caller. Agents' eight scripts are kept as they are and wrapped by a dispatcher (§4.2); `queue-mvp`, an experiment, gets no verb.
- Plugins and marketplace (§5, lines 109-130): plugin ids become `<tool>@agentik`, with relay and agents taking short names (D2); plugin code calls the dash name, never the front door, so each plugin needs only its own tool; one `agentik` marketplace with five `git-subdir` entries, `ref` pins coming with r2 tags; the owner's machine installs from a local `file://` copy of the same file (D1); every per-repo `marketplace.json` is deleted because two install paths would load the hooks twice. Sessions started before the switch keep their old namespaces (§5.3).
- Live-file inventory (§6, lines 132-198): "live" means tracked and outside `design/`, `bugs/`, `history/`, `NICE_TO_HAVE.md` and `CHANGELOG*`, with the exceptions that start-line briefs and each running chain's newest charter are live. Per-repo counts of files with the old prefix over files with any old name: relay 6/52, session 20/61, decisions 12/18 plus 4 briefs, respeak 18/20, agents 21/22, the org profile 1/1. Migrations of state folders and keys are listed as c1 to c19 (§6.3): only names change, readers take the new path else the old, folders move only in a cold window by `mv` plus a symlink back, and r2 removes fallbacks.
- Commons (§7, lines 200-226): layout; the guide takes over the session tool's `design/conventions.md` sections 1 to 9 and adds a naming, verbs, exit-code, docs, README and install table; shared code now is `scripts/hygiene`, `scripts/bounded` and the front door, later `doclint` (one copy in r2); repos get them as vendored copies pinned by sha256, because a shared Python library could not serve the Go repo.
- Rollout (§8, lines 228-303): step 0 amends four entries in the owner's private portfolio ledger; the commons packet goes first with no live effect; tool packets run in parallel and merge only in the switch because four old marketplaces read the checkouts and one reads the public respeak repo (line 245, edited by the final commit e456f4b); the switch has five steps (§8.3); the cold window needs no `claude`, no launcher and no relay night (§8.5); r2 removes aliases on or after 2026-12-31 and bumps each tool's major version (§8.6).
- Acceptance and proofs (§9, lines 305-322): A1 to A9 are acceptance lines; P1 to P3 are proofs still to run: P1 a `file://` `git-subdir` entry installs and its hooks run in a scratch config folder (if it fails, D1 falls back to the public marketplace), P2 a disabled plugin's cache and hooks survive for a session that loaded it (if not, the switch waits for older sessions to end), P3 `uv tool install` after the uninstall gives both command names.
