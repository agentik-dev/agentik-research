## Numbers and claims to correct

1. **Background work at the end of a child run.** The design assumes a completed `claude -p` ends background work with the final result. The Claude Code changelog (<https://code.claude.com/docs/en/changelog>) dates that: from 2.1.163 (June 2026) to 2.1.291 a completed `-p` run stopped background shells about five seconds after the final result; 2.1.292 (6 October 2026) waits for them, and while a background command runs the 10-minute idle cap does not end the wait. Fix: re-check the orphan sweep, the stall rule and the wall against a child that now waits; state the version the rules were tuned on.

2. **Child environment.** `design/relay-r1.md` line 167 says a nested `claude` spawn is its own session with its own hooks, so `CLAUDE*` variables are stripped. The "Environment variables" page (<https://code.claude.com/docs/en/env-vars>) says Claude Code sets `CLAUDECODE=1` and `CLAUDE_CODE_CHILD_SESSION=1` in the subprocesses it spawns, and neither recommends nor forbids stripping. Fix: say the stripping is the relay's choice, and say which variables the child sees and why.

3. **Print-mode permissions.** `design/relay-r1.md` line 175 says that in print mode `--permission-mode auto` denies every Write and Bash unless `--allowedTools` pre-allows them (CLI 2.1.280). The pages "Run Claude Code programmatically" (<https://code.claude.com/docs/en/headless>) and "Choose a permission mode" (<https://code.claude.com/docs/en/permission-modes>) say a prompt with no host to answer it is denied and the run continues, that auto mode uses a classifier and pauses after 3 consecutive or 20 total blocks (in `-p` the action just does not run), and that an unavailable auto mode falls back to Manual. "Denies every Write and Bash" is not in the documentation. Fix: re-test on the current version and quote the documented behaviour; keep `permission_denials` as the authoritative record of denials (Agent SDK TypeScript reference, <https://code.claude.com/docs/en/agent-sdk/typescript>).

4. **Budget overshoot.** The row budget becomes the child's `--max-budget-usd` (`internal/night/plan.go` line 1004). The Agent SDK page "How the agent loop works" (<https://code.claude.com/docs/en/agent-sdk/agent-loop>) says the budget is checked after each response and is a client-side estimate, so spend can pass the cap by one response plus any running subagents. The night cap `--max-usd` is compared before each pick and never kills a running sitting, so a night can overshoot by the running rows' budgets (`internal/night/night.go` lines 1496 and 1620 to 1630, by the site's reading). Fix: document both overshoots in the README's money section.

5. **Bash tool cap.** `design/relay-r1.md` line 96 plans around a 600-second Bash cap (`VerifyOnceSeconds` 540). The "Tools reference" (<https://code.claude.com/docs/en/tools-reference>) gives 600,000 milliseconds as the ceiling and 120,000 as the default, and a timed-out foreground command moves to the background. Fix: state both numbers and whether the child's verify line can be backgrounded against the relay's wishes.

6. **Usage-limit event fields.** `design/usage-limit-resume-r1.md` lines 7 to 17 and 89 call the stream's `rate_limit_event` fields unpublished and use `rateLimitType`. The Agent SDK references (<https://code.claude.com/docs/en/agent-sdk/python> and the TypeScript page) document `rate_limit_type` with values `five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet` and `overage` in Python and `resetsAt` in TypeScript; the wire spelling the relay reads is unconfirmed. Fix: cite the SDK pages, test the spelling on the current CLI, and handle the two per-family values.

## Claims the documentation supports, for the record

The `subagents/` transcript directory is documented ("Create custom subagents"); stream watchdogs are 180 seconds to first byte, 300 between events and 180 between bytes ("Enterprise network configuration"), and a stalled subagent in a workflow restarts after 600,000 milliseconds at most five times; no main-session progress watchdog is documented, so the relay's outside watchdog fills a real gap. Hooks fail open on a timeout unless `onFailure` is `"block"` (2.1.295); the sandbox covers Bash, PowerShell and Monitor commands only and is off by default ("Configure the sandboxed Bash tool"). Worktrees live at `.claude/worktrees/<name>/` with four isolation checks that do not track shell writes ("Run parallel sessions with worktrees"); git keeps the index and HEAD per worktree and shares refs, and its lockfile page says a second locker fails at once.
