## Numbers and calculations to correct

1. **The inline-or-retrieve model ignores cache pricing.** `history/design/decisions-r1.md` section 8.3 prices always-loaded text at its size times the number of turns and a lookup at one extra turn that re-reads the context, giving a break-even near 667 tokens with assumed values (300 turns, 100k tokens of context, 2 lookups per sitting). The Anthropic "Pricing" page (<https://platform.claude.com/docs/en/about-claude/pricing>) prices a cache read at 0.1x base input, 0.05x on Opus 5.5 and Sonnet 5.5, and 0.025x on Fable 5.1, and a write at 1.25x (five-minute lifetime) or 2x (one hour). Both sides of the model are mostly cache reads, so the threshold likely holds to first order, but the dollar figures do not. Fix: restate the model in cached-read terms per model, and add the miss term: a gap past the lifetime, a model switch, a tool-definition change, compaction or an upgrade reprices the whole context at the write rate.

2. **The "2.8x rise".** `history/design/decisions-r1.md` section 8.2 mentions a 2.8x rise with no source. Fix: cite it or remove it.

3. **The caps of 25 and 7.** `design/d17-four-verbs.md` and `src/decisions/ledger.py` line 40 state the caps with no reason, and they count entries, not bytes. The site found no outside source for either number; the nearest evidence is that adherence falls with instruction count (Jaroslawicz et al., "How Many Instructions Can LLMs Follow at Once?", 2025: Claude Sonnet 4 at 94.4 percent with 100 instructions and 42.9 with 500) and the documentation's advice to keep CLAUDE.md under 200 lines (<https://code.claude.com/docs/en/memory>). Fix: record the caps as rulings with the date, and measure the generated block's bytes at the cap (seven entries of the consumer's typical 2,000 to 3,500 bytes would put 14 to 25 KB in every session).

4. **Imports and the file hierarchy.** `history/design/decisions-r1.md` section 9 says Claude Code expands `@`-imports at launch and that a parent CLAUDE.md taxes every repository beneath it. The memory page confirms imports load at launch, nest to four hops and save no context, and the "Set up Claude Code in a monorepo" page (<https://code.claude.com/docs/en/large-codebases>) confirms parent files load at launch with `claudeMdExcludes` to skip one. The same memory page says CLAUDE.md is a user message after the system prompt with no compliance guarantee, that the root file returns after compaction and nested files load again on demand, and that auto memory loads the first 200 lines or 25KB of `MEMORY.md`. Fix: cite the pages, and resolve the tension between the first design's ban on parent-file content and the d17 cross-repo block rendered into a user-level CLAUDE.md.

5. **Skills.** `history/design/decisions-r1.md` section 4.2 says a skill loads its description at start and its body on use, under 500 lines.
