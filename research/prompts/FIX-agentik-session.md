# Fix prompt: agentik-session

Paste into a Claude Code session in the agentik-session repository. The research site read the repository at commit e7f0723 on 2026-10-14 and checked its claims about Claude Code against Anthropic's documentation on the same day. Each item below gives the location the site's notes recorded, what the repository says, what the vendor page says, and the fix. Verify each location first; the repository may have moved on. Open each vendor page before editing, because the pages are undated and change often. Change documentation, comments and data tables, not behaviour, unless an item says the behaviour rests on the wrong number. Commit per item with a message that names the vendor page and the date.

## Numbers and claims to correct

1. **Model windows table.** `claude_session/profiles.yaml` lines 13 to 19 list opus, sonnet and haiku at 200,000 tokens and give 1M only to fable, mythos and `opus[1m]`. As of 2026-10-14 the Anthropic page "Context windows" (<https://platform.claude.com/docs/en/build-with-claude/context-windows>) gives a 1M window to the Fable and Mythos models, Opus 4.6 and later, Sonnet 4.6 and later, and Haiku 5.5; Sonnet 4.5 and older have 200K. The Claude Code page "Model configuration" (<https://code.claude.com/docs/en/model-config>) says Claude Code defaults Fable, Sonnet 5 and later, Haiku 5.5 and Opus 4.7 and later to 1M, needs the `[1m]` suffix for Opus 4.6 and Sonnet 4.6, and compacts at about 967K tokens on a 1M model. Fix: update the table per model version, or state in the README that the table is deliberately cautious and why. The role ceilings of 180,000 tokens apply on both windows, so only the orchestrator roles change.

2. **Prompt-cache lifetimes.** `NICE_TO_HAVE.md` lines 108 to 111 say the main loop uses a one-hour cache lifetime and subagents five minutes. The Claude Code page "How Claude Code uses prompt caching" (<https://code.claude.com/docs/en/prompt-caching>) says the one-hour lifetime applies to the main conversation only on a subscription within plan usage; on usage credits, an API key or a cloud provider it is five minutes, and `promptCacheTtl` and `subagentPromptCacheTtl` (`5m` or `1h`, Claude Code 2.1.242 or later) set each bucket. Fix: state the condition, and make the idle-wake cap (proposed at 3,300 seconds) read the lifetime in force rather than assume one hour.

3. **Cache read price.** The same lines say a one-hour write costs 2x and a read 0.1x. The Anthropic "Pricing" page (<https://platform.claude.com/docs/en/about-claude/pricing>) gives write multipliers of 1.25x (five minutes) and 2x (one hour), and read multipliers of 0.1x for most models but 0.05x on Opus 5.5 and Sonnet 5.5 and 0.025x on Fable 5.1. Fix: the 4.8 million rewritten tokens in the cache audit were priced at the wrong read rate if any 5.5 or Fable 5.1 model was involved; recompute the audit's dollar estimate per model, and quote the multipliers per model.

4. **Cost model.** `design/overhaul-r1.md` section 8 states cost as turns times context. By the pricing page, a turn is priced as uncached input, a cache write or a cache read plus output, so cost is turns times context only while the cache is warm; each miss reprices the whole context at the write rate. Example from the documented prices: reading a warm 200,000-token context on Opus 5.5 costs about 0.04 dollars, a cold one-hour rewrite 1.60, and a cold five-minute rewrite 1.00. Fix: add the miss term to the model and name what causes a miss (a gap past the lifetime, a model switch, a tool-definition change, compaction, an upgrade).

5. **Hook timeout.** `design/review-r6.md` finding C3 says the default hook timeout is 60 seconds. The "Hooks reference" (<https://code.claude.com/docs/en/hooks>) gives 600 seconds for a command hook, 30 for a prompt hook and 60 for an agent hook. Fix: correct the finding and any constant derived from it.

6. **Stop hook cap.** `plugin/hooks/run` keeps a shim so an exit 2 on Stop holds every turn end. The "Automate actions with hooks" page (<https://code.claude.com/docs/en/hooks-guide>) says a Stop hook's exit 2 is overridden after 8 consecutive blocks with no tool call between them. Fix: document the cap beside the shim.

7. **Idle compaction conditions.** `NICE_TO_HAVE.md` line 82 says `idleCompaction` fires after about 54 idle minutes above 200,000 tokens. The "Settings reference" (<https://code.claude.com/docs/en/settings-reference>) adds the conditions: interactive sessions, the one-hour cache lifetime, version 2.1.290 or later, and `autoCompactEnabled: false` also stops it. The hook payload's `trigger` value for an idle pass is not documented. Fix: add the conditions; keep the `trigger: "auto"` observation labelled as observed on 2.1.296.

8. **PreCompact stdout.** `claude_session/hooks.py` lines 517 to 531 and the charter `history/sittings/2026-10-11-3-c1-fix.md` say a passing PreCompact hook's stdout is read as compaction instructions. The hooks reference does not document this; its general rule sends a passing hook's stdout to the debug log. Fix: label it as observed on 2.1.296 and add a check that fails loudly if the behaviour changes.

9. **Background work at the end of a print-mode run.** `bugs/2026-09-12-overnight-window.md` records that a completed `claude -p` killed four background builders. The Claude Code changelog (<https://code.claude.com/docs/en/changelog>) dates that behaviour: from 2.1.163 to 2.1.291 a completed `-p` run stopped background shells about five seconds after the final result; 2.1.292 (6 October 2026) waits for them, and while a background command runs the 10-minute idle cap does not end the wait. Fix: date the bug's premise and note the change in the respawn and relay-child designs.

10. **`--max-turns` and `--max-budget-usd`.** The README says `--max-turns` caps the turn ceiling. The "CLI reference" (<https://code.claude.com/docs/en/cli-reference>) says both flags work in print mode only, default to no limit, and that the budget is a client-side estimate that can pass the cap; the Agent SDK page "How the agent loop works" (<https://code.claude.com/docs/en/agent-sdk/agent-loop>) says it is checked after each response, so spend can pass the cap by one response plus any running subagents. Fix: say print mode only and name the overshoot.

11. **Bash tool timeout.** If any profile or runbook figure assumes a 600-second Bash default: the "Tools reference" (<https://code.claude.com/docs/en/tools-reference>) gives a default of 120,000 milliseconds and a ceiling of 600,000, and a timed-out foreground command moves to the background.

12. **Scheduled wake lands late.** `NICE_TO_HAVE.md` lines 108 to 111 observe a 3,600-second wake landing at 3,636 to 3,648 seconds. The page "Run prompts on a schedule" (<https://code.claude.com/docs/en/scheduled-tasks>) documents no such delay and says a self-paced `/loop` waits between 1 minute and 1 hour and `/loop 5m` runs at 4 minutes 45 seconds to keep the five-minute cache warm. The cloud-or-session question for a `/loop` of 60 minutes or more (`NICE_TO_HAVE.md` line 55) is also undocumented. Fix: keep both as observations with the version, and build the idle cap against the lifetime in force.

13. **"Hard stop".** `README.md` line 3 says a budget with a hard stop; `design/overhaul-r1.md` line 74 says the meter never blocks and the model exits by rule. Fix: say in the README that the stop is a signal, a rule, and an outside kill under the relay.

## Claims the documentation supports, for the record

Helpers count toward the same usage limits as the main conversation; `claude -p` is offered no wait at a limit; `autoContinueAtUsageLimit` defaults to true from 2.1.234, covers only interactive claude.ai sessions and re-arms at most twice; Fable can bill usage credits and `-p` bills them without asking ("Subagents", "Interactive mode" and "Model configuration" pages). A permission prompt with no host is denied and the run continues, with the denials in the result's `permission_denials` list ("Run Claude Code programmatically"). The transcript path and the `subagents/` directory are documented, with the format marked unstable ("Manage sessions", "Create custom subagents"). A timed-out PreToolUse hook fails open unless `onFailure` is `"block"` (2.1.295).
