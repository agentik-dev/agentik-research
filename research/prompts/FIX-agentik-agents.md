## Numbers and calculations to correct

1. **The price table.** The cost tool's `PRICES` table (cached 2026-10-06) gives cache-read rates of 0.20 dollars per million tokens on Opus 5.5 and Sonnet 5.5 and 0.25 on Fable 5.1, and 0.10x input for the rest; its comments say a 1-hour write (2.0x) is not tracked and that `[1m]` bills a premium above 200K tokens. The Anthropic "Pricing" page (<https://platform.claude.com/docs/en/about-claude/pricing>) as of 2026-10-14: base prices Fable 5.1 10 and 50 dollars per million input and output tokens, Opus 5.5 4 and 20, Sonnet 5.5 2 and 10, Haiku 5.5 0.10 and 0.50; cache read 0.1x, except 0.05x on Opus 5.5 and Sonnet 5.5 and 0.025x on Fable 5.1; cache write 1.25x (five-minute lifetime) and 2x (one hour); batch 50 percent off. Pricing is the same across the 1M window for Claude 4.6 and later, so there is no `[1m]` premium above 200K; only Haiku 5.5 charges more above 100,000 prompt tokens (0.50 and 2.50). Fix: correct the `[1m]` comment, price Haiku 5.5's tier (`NICE_TO_HAVE.md` already notes it is unpriced), and track one-hour writes where a subscription session would get them.

2. **Which runs get the one-hour cache.** The "How Claude Code uses prompt caching" page (<https://code.claude.com/docs/en/prompt-caching>) says the main conversation gets the one-hour lifetime only on a subscription within plan usage; on an API key it is five minutes; subagents, forks and compaction get five minutes. The API lane's `--bare -p` runs on a key therefore see five-minute writes. Fix: price the API lane's cache writes at 1.25x and say so in "Prompt cache economics".

3. **Billing follows the credential.** The support page "Use the Claude Agent SDK with your Claude plan" (<https://support.claude.com/en/articles/15036540-use-the-agent-sdk-with-your-claude-plan>) says Anthropic paused the changes announced for 15 June 2026 and that on a plan login SDK and `claude -p` usage counts against plan limits; "Monthly API credits for Max and Team plans" (<https://support.claude.com/en/articles/17154008>) says Max and Team include monthly API credits for the SDK and the API, not for interactive Claude Code, and `claude -p` counts only with a key from the linked organization. "Authentication" (<https://code.claude.com/docs/en/authentication>) says a `-p` run always uses `ANTHROPIC_API_KEY` when it is set and `--bare` never reads the login. Fix: state in the README which credential each lane uses and what that does to plan limits.

4. **What a base URL turns off.** `design/01-local-agent-lane.md` section 4 says a gateway loses Remote Control. "Connect Claude Code to an LLM gateway" (<https://code.claude.com/docs/en/llm-gateway-connect>) says Remote Control is off under a non-Anthropic base URL, and voice dictation and Remote Control are off while a key, token or helper is active; "Other LLM gateways" (<https://code.claude.com/docs/en/llm-gateway>) says a base URL alone keeps the login, a credential replaces it and ends plan limits, and Anthropic does not support non-Claude models behind a gateway. Fix: list what the loopback router turns off, and separate voice dictation (keys) from Remote Control (base URL).

5. **Claude Code constants the design relies on.** `design/01-local-agent-lane.md` sections 2.3 and 5.2 cite a 300-second stream watchdog, an `API_TIMEOUT_MS` default of 600000, 20 concurrent subagents and a spawn depth of 3. "Enterprise network configuration" (<https://code.claude.com/docs/en/network-config>) gives 180 seconds to first byte, 300 between events and 180 between bytes. Fix: cite the page for the watchdogs, and cite or re-measure the other three.

6. **`--max-budget-usd` overshoot.** The README measures a 1.2x overshoot and deflates per-shard ceilings by 1.35. The Agent SDK page "How the agent loop works" (<https://code.claude.com/docs/en/agent-sdk/agent-loop>) says the budget is checked after each response and is a client-side estimate, so spend can pass the cap by one response plus any running subagents. Fix: cite it as the reason, and note that the overshoot scales with response size rather than being a fixed ratio.

## Claims the sources support, for the record

Routers route on query difficulty, none on privacy, and several lose to the best single model (Ong et al., RouteLLM, 2024; Li et al., LLMRouterBench, 2026); Anthropic's own advice is to sweep effort before switching models (<https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence>). Ollama's Anthropic-compatible endpoint lacks prompt caching, `tool_choice` and `count_tokens`, and its documentation advises 64,000 tokens of context or more for agents (<https://docs.ollama.com/api/anthropic-compatibility>, <https://docs.ollama.com/context-length>). Two practitioners report 20 to 610 tokens a second of prompt processing and 23 to 31 of generation on other local models; the repository's 11 tokens a second for prose is the same order.
